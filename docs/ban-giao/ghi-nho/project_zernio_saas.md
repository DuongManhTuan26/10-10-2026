Commercial AI sales SaaS ("Zernio AI Sales") at `/Users/mac/projects/zernio`, taken over 2026-08-17 from an abandoned Google AI Studio vibecoding session (repo `DuongManhTuan26/giaodienmoinhat`). Separate from [[project-fanpage-ai-system]], which was the user's *internal* tool.

**Product:** multi-tenant SaaS for shop owners selling on social media. Connects social accounts through the third-party **Zernio API** (so customers avoid each platform's own app-review process). Four AI functions: writes/schedules posts, runs ads, sells in DMs (collect 5 fields → close order → Telegram report), and does daily analytics.

**Stack:** React 19 + Vite + Tailwind (frontend, design finished and must be preserved), Express + TypeScript (backend under `server/`), PostgreSQL on Neon, **OpenRouter** for AI (NOT Gemini — user switched 2026-08-17). Models chosen per task because cost is the user's COGS: sales replies → `anthropic/claude-sonnet-5`, JSON extraction → `google/gemini-3.7-flash`. Measured: extraction $0.0007/call, sales reply $0.002/call, 2 post drafts $0.0087.

**Status as of 2026-08-17: all 10 screens wired to real data, `mockApi.ts` (1224 lines of fake data) deleted.** 26/26 endpoints return 200; 9/9 data endpoints reject unauthenticated requests; webhook rejects unsigned and wrong-signature; multi-tenant isolation verified (a second shop sees 0 of the first shop's orders/conversations/accounts and cannot adopt its Zernio profile).

**Zernio API gotchas — all found by live probing, docs are WRONG or silent on these. Do not trust the docs here:**
- Send message: docs show `{text}`; real contract is `{accountId, message}`. Following the docs means AI never delivers a single reply.
- Create post: needs `platforms: [{platform, accountId}]` (not a flat `accountIds`) **and** `publishNow: true` — without the latter Zernio silently stores a draft and never publishes. Use `x-request-id` header as the idempotency key.
- HTTP 200 on post create means *accepted*, not *published*. Final status only arrives via `post.published` / `post.partial` / `post.failed` webhooks.
- Platform id for X is `twitter`; `x` is rejected. Snapchat returns 403 (beta). Google Business is `googlebusiness`.
- **Meta Ads is not separately connectable** — it appears as a child account (`parentAccountId`) auto-created when Facebook is connected with ads permissions.
- Ads endpoints need `adAccountId` = Meta's `act_...` id, obtained via `GET /ads/accounts?accountId={zernioAccountId}`. Passing the Zernio account id causes "adAccountId is required".
- `GET /inbox/conversations/{id}` requires an `accountId` query param.
- TikTok has **no** inbox API at all (no DMs, no comments) — post-only. Verified capability matrix lives in `server/platforms.ts`.
- Webhook signature is HMAC-SHA256 **hex, bare** (no `sha256=` prefix).

**Own-code gotchas worth remembering:** `ON CONFLICT` cannot use a *partial* unique index unless the conflict clause repeats the `WHERE` predicate. `pool.on('error')` only catches idle-client errors — a client borrowed mid-query emits `'error'` on itself and an unhandled one kills the process (this crashed the server on 2026-08-17; fixed with `pool.on('connect')` + `keepAlive`).
